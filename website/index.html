THE PROBLEM

Agents can fail in ways
a better prompt cannot fix.

Useful agents need more than a longer context window. They need a way to manage what they remember, constrain what they do, and inspect what happened.

01 / CONTEXT
◈

Relevant context gets lost

Naive history replay grows without bounds. Stale or superseded facts can keep influencing new decisions.

02 / EXECUTION
⌁

Tool calls can repeat

Retries and loops can multiply side effects. A model saying “done” does not prove an external action succeeded.

03 / DIAGNOSIS
⌘

Failure evidence is fragmented

Without a connected run record, it is harder to understand which context was selected and where execution stopped.

WHAT SYNAPSE BRINGS TOGETHER

One layer. Four useful primitives.

Start with the part your application needs. Keep your existing agent framework and deployment decisions.

◈MEMORY

Memory that has a lifecycle

Ingest, deduplicate, retrieve, update, supersede, and retract information instead of replaying an ever-growing transcript.

  • Hybrid lexical + vector retrieval with rank fusion
  • Temporal validity and source/provenance metadata
  • Token-budgeted context packing

FIRST STEP

Try the memory layer
on your machine.

The published package supports a local SQLite evaluation path. It is the easiest way to test the write-and-retrieve flow before provisioning production infrastructure.

Read the developer quickstart →

Python 3.10+ · local-only evaluation · no external database required

TERMINAL
python -m pip install synapse-memory-engine==1.3.1
PYTHON
from synapse_memory import SynapseClient

with SynapseClient(
    "http://127.0.0.1:8008",
    tenant_id="local-dev",
) as client:
    saved = client.create_memory(
        "The app uses SQLite for local evaluation.",
        category="fact",
    )
    result = client.retrieve("Which database is used locally?")
    print(saved.id)
    print(result.fused_context)

TRUST BY BEING PRECISE

Security details
should be explicit.

Synapse documents its boundaries so developers can decide whether its data model and deployment requirements fit their workload.

Read the security policy ↗
01

Field-level encryption has a defined scope

The authoritative content field is Fernet-encrypted. The plaintext search projection, text-search derivative, and embeddings remain readable by design; protect database volumes and backups accordingly.

02

Tenant isolation depends on deployment roles

PostgreSQL RLS must be paired with the documented non-owner, non-superuser runtime role and migrate-then-run setup.

03

Run evidence is metadata-only

Trace events are designed to exclude prompts, raw tool arguments, tool results, and memory text. Applications remain responsible for safe event metadata.

04

Validation status is not overstated

CI and synthetic fault-injection tests are not customer-workload proof, a security certification, or a production-readiness guarantee.
